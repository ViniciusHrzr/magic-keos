# Milestone v1.0: Magic Kéos MVP

**Status:** ✅ SHIPPED 2026-05-15
**Phases:** 1–4
**Total Plans:** 11

## Overview

Estabilizou o app companion de RPG Magic no Universo Kéos: corrigiu persistência, race condition de hidratação, re-renders desnecessários e error boundaries (Phase 1); adicionou validação de entrada e limpeza de código morto (Phase 2); extraiu componentes do grimório e adicionou persistência de filtros de sessão (Phase 3); entregou a aba "Regras" com referência in-session e o seletor de Proficiências por chips (Phase 4).

## Phases

### Phase 1: Estabilidade de Fundação

**Goal**: O app persiste dados de forma confiável, hidrata sem corrida e isola crashes sem derrubar a sessão de jogo
**Depends on**: Nothing (first phase)
**Plans**: 3 plans (2 waves)

Plans:
- [x] 01-01: Debounce de escrita e memoização do CharacterContext (FOUND-01, FOUND-04)
- [x] 01-02: Error boundaries globais e por aba (FOUND-03)
- [x] 01-03: Loading state de hidratação e guards nas screens (FOUND-02)

**Success Criteria achieved:**
1. ✓ App não trava ao digitar em campos de texto (debounce 500ms + memoização)
2. ✓ App exibe dados corretos sem flash de estado vazio na hidratação
3. ✓ Erro de render em uma aba não derruba as demais
4. ✓ Alterar campo em uma aba não causa re-render das abas não dependentes

**Cross-cutting constraints:**
- `store/CharacterContext.tsx` modificado por 01-01 e 01-03 — mudanças aditivas e não conflitantes
- Nenhuma lógica de funcionamento da ficha foi alterada

## Milestone Summary

**Key Decisions:**

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| React Context + AsyncStorage (não Zustand) | Simplicidade para o tamanho atual do app | ✓ Good — memoização via useMemo/useCallback suficiente |
| Debounce 500ms | Balanceia responsividade vs. frequência de escrita no Android | ✓ Good |
| useCallback([update]) em todos os set* | Previne re-renders desnecessários em filhos que dependem de setters | ✓ Good |
| useMemo no contextValue | Provider value estável = zero re-renders extras no tree | ✓ Good |
| NumericStepper para IP (min=0 default) | Zero código novo de validação — usa contrato existente do componente | ✓ Good |
| Module-level vars para persistência de filtros | Simples, sem Context — persiste enquanto o processo está vivo | ✓ Good |
| SpellDetailCard compartilhado magia↔grimório | Elimina duplicação sem abstrair demais | ✓ Good |
| Aba Regras como conteúdo estático flat (sem accordion) | Referência de sessão — acesso rápido é mais importante que organização compacta | ✓ Good |
| Chips com key `pericia:nome` | Evita colisões entre proficiências de perícias diferentes com nomes iguais | ✓ Good |

**Issues Resolved:**

- Race condition de hidratação: state vazio flashava antes dos dados carregarem
- Re-renders em cascata: alterar qualquer campo causava re-render de toda a árvore
- Glyphs de mana exibindo caracteres errados no cold start (fonte não carregada)
- modal.tsx e explore.tsx: arquivos inacessíveis/duplicados removidos
- COLOR_HEX e GRAU_COLORS duplicados em magia.tsx e grimorio.tsx: consolidados

**Issues Deferred:**

- FICHA-04: index.tsx > 300 linhas — extração de InstanceBlock para componente separado (v1.1 backlog)
- AsyncStorage sem versão de schema em migrate() — fragilidade se schema mudar significativamente

**Technical Debt Incurred:**

- migrate() sem campo de versão no schema — acumulação de guards por tipo ao invés de versão semântica
- Filtros do grimório persistem via module-level vars (processo-vivo apenas) — não sobrevivem a kill do app; solução aceitável para v1
