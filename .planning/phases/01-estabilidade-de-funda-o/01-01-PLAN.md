<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| AsyncStorage → CharacterProvider | Data read from device storage on app launch; malformed JSON or corrupted data enters here |
| User input → setAllChars | User text entered in screens flows through set* functions into state and eventually to AsyncStorage |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | AsyncStorage debounce timer (debounceRef) | accept | Timer only delays persistence write; React state updates immediately, so UI data integrity is not affected by debounce window |
| T-01-02 | Denial of Service | AsyncStorage.setItem fire-and-forget | mitigate | Add .catch(err => console.error(...)) to all fire-and-forget calls per D-02 — failures are logged, not swallowed silently |
| T-01-03 | Information Disclosure | console.error in .catch handlers | accept | Error messages contain storage key names and serialized error objects; these are developer-only logs in a local-only app with no network telemetry |
| T-01-04 | Tampering | useMemo contextValue dependency array | accept | If a dep is accidentally omitted, consumers receive stale callbacks — mitigated by explicit exhaustive dep list matching all set* functions |
| T-01-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this plan — all changes are in-place code modifications using existing React/AsyncStorage APIs |
</threat_model>
