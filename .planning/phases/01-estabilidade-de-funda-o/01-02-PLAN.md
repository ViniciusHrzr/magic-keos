<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| React render tree → ErrorBoundary | Render errors thrown by child components are caught here; error objects cross this boundary |
| componentDidCatch → console.error | Error details (stack traces, component stacks) are logged to device console |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | componentDidCatch console.error | accept | Stack traces logged to device console only; no network transmission; developer-facing; local-only app with no telemetry |
| T-02-02 | Denial of Service | ErrorBoundary render loop | accept | React's getDerivedStateFromError is called once per error event; hasError=true prevents re-render of children, stopping infinite loops |
| T-02-03 | Elevation of Privilege | ErrorBoundary catching async errors | accept | React ErrorBoundaries only catch synchronous render errors, not async promise rejections — async errors in useEffect remain unhandled (pre-existing behavior, not introduced here) |
| T-02-04 | Tampering | Error message content | accept | The error message is hardcoded in the component; not user-controlled input |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed — ErrorBoundary is implemented using React's built-in class component lifecycle methods |
</threat_model>
